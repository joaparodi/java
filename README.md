<!-- # Este trabajo práctico de desarrollo web con HTML5 y CSS3 nativo me sirvió para entender cómo maquetar una interfaz web desde sus cimientos, sin depender de librerías ni scripts de JavaScript.  En las primeras prácticas abordé la estructura del código mediante elementos semánticos de HTML. Aprendí a vincular recursos externos abriendo enlaces en pestañas independientes con target="_blank", a jerarquizar la información con listas ordenadas e desordenadas, y a organizar información en tablas usando <thead>, <tbody>, <tfoot>, colspan y rowspan. También comprendí la importancia de la accesibilidad al crear formularios vinculando cada <label> a su <input> con el atributo for.  A nivel de CSS, el primer gran descubrimiento fue entender cómo funciona realmente el modelo de cajas. Noté que al definir el tamaño de un elemento con el valor por defecto (content-box), agregarle un padding o un border hacía que la caja se ensanchara más de lo planeado y rompiera el diseño. Al adoptar box-sizing: border-box como regla universal en el proyecto, comprendí que todos los rellenos quedan contenidos dentro del ancho especificado, logrando un control de medidas exacto.  Para la distribución de los elementos integré Flexbox y CSS Grid. Con Flexbox maqueté la barra de navegación alineando el logo y los enlaces mediante justify-content: space-between y align-items: center. Para las tarjetas utilicé flex-wrap: wrap junto a flex: 1 1 280px, lo que permite que se acomoden en varias filas de forma fluida según el espacio en pantalla. En la galería tipo mosaico utilicé CSS Grid con repeat(auto-fill, minmax(180px, 1fr)). En este punto me di cuenta de que al estirar tarjetas a dos columnas o filas (span 2), quedaban espacios en blanco al saltar de línea. Al investigar la regla grid-auto-flow: dense, descubrí que el navegador reorganiza automáticamente las piezas más pequeñas ubicadas más abajo en el HTML para rellenar los huecos vacíos sin dejar agujeros en la interfaz.  En cuanto a las interacciones sin uso de JavaScript, comprendí que la única forma estándar de mantener la "memoria" de un clic en CSS es aprovechar el estado de un <input type="checkbox"> o <input type="radio">. Al ocultar el control y asociarlo a un <label>, se puede utilizar la pseudo-clase :checked combinada con el selector de hermanos (~) para controlar el despliegue del menú hamburguesa o alternar entre las pantallas de un formulario por pasos.  Para la validación del formulario en tiempo real, combiné los atributos nativos de HTML (required, type="email") con las pseudo-clases :valid e :invalid. Noté un problema: los campos obligatorios nacían pintados de rojo de entrada. Descubrí que al usar :invalid:not(:placeholder-shown), el borde rojo y el mensaje de error solo se muestran una vez que el usuario empieza a escribir, evitando alertas falsas.  Finalmente, me pareció clave centralizar la paleta de colores en :root mediante variables CSS (var()). Esto facilitó implementar un Modo Oscuro simplemente redefiniendo esas variables dentro de una clase. Todo este aprendizaje se consolidó en la Landing Page final, donde sumé animaciones @keyframes, un carrusel móvil usando scroll-snap y la adaptación responsiva mediante @media queries.   -->
